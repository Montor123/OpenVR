## Funcionamiento local y sincronización opcional

La experiencia base usa el usuario local de Android, Package Manager, ajustes y diagnóstico local. Inicio conserva favoritos y hasta ocho lanzamientos recientes en preferencias privadas de la app. Ajustes consulta el tipo de red activa mediante la API de estado de red local. Las APK se instalan desde un archivo elegido por el usuario. Los recursos de la interfaz, las APK y los registros permanecen en el equipo. Las descargas de herramientas y dependencias son una fase de preparación. El lanzador carece de permiso de Internet y el script de Cuttlefish configura la estadística anónima del anfitrión como desactivada. La demo 0.1.0 superó el healthcheck después de arrancar en Docker con `--pull=never --network none --read-only` y un volumen de resultados. El ensayo verifica el arranque del servidor y su endpoint local dentro del contenedor. El arranque autónomo y el recorrido de APK de Cuttlefish con la máquina desconectada siguen pendientes.

La siguiente prueba offline se realiza después de preparar el invitado y las herramientas. Desconectar la salida a Internet sin perder el acceso local a ADB y a la pantalla del invitado. Arrancar una instancia limpia, resolver HOME, abrir Ajustes, instalar la APK de prueba y reiniciar para verificar que el lanzador y la actividad siguen disponibles. Registrar los resultados y cualquier requisito de conexión que introduzcan las aplicaciones instaladas o el invitado. En el visor original, los requisitos del modo desarrollador siguen siendo los de Horizon OS. [Modo desarrollador y ADB de Meta](https://developers.meta.com/vr/documentation/native/android/mobile-device-setup/)

**Sincronización futura.** La fuente principal será el estado local. El primer incremento de esta función puede demostrar exportación e importación manual con un formato versionado para preferencias y favoritos seleccionados. El usuario revisará también los identificadores de las apps elegidas antes de guardar o restaurar una copia. El esquema debe permitir validar tamaño, versión e integridad, y mostrar los conflictos de restauración antes de reemplazar el estado. Este flujo se puede probar con archivos locales.

Si más adelante se añade transporte, la misma exportación podrá guardarse de forma voluntaria en un almacenamiento elegido por el usuario mediante un adaptador independiente. Se prevé cifrar el contenido en el cliente y conservar las claves bajo control del usuario. Debe ser posible desconectar el transporte, retirar sus credenciales y continuar operando localmente. APK, historiales de uso, inventarios de paquetes, registros ADB, datos de sensores y cuentas de plataforma quedan fuera del alcance inicial de sincronización. El alcance actual comprende el diseño, sin proveedor, cuentas, servicio remoto ni implementación de red.
